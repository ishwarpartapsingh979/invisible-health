PRD — Feature Summary & Feature Details

Priority by user value · integrations mapped · login-first with “Continue without login”.

Feature Summary

The product: the hyper-personalization of a personal trainer × the sensory pull of a group class, voice-first — so a high-stress professional actually shows up every day. Every session is grounded in a pro-athlete coach’s system, tuned to your context and the time you have, and wrapped in a live, adaptive audio experience (coach + music + vibe) you crave.

Priority = how central it is to why the user uses the app (the experience is the product → P0 even where hardest to build). User #1 (Fitness) is primary; User #2 (Steps) is the low-friction wedge; meditative is low.

Feature Details

Foundational (shared)

Frictionless Start P0

  • Login-first, non-blocking: the first screen leads with “Sign in with Apple” as the primary, encouraged action (framed with the benefit — save your progress & sync across devices), and a clear secondary “Continue without login.” We nudge toward login, but never force it.
  • Continue-without-login → anonymous identity: device UUID in Keychain (survives delete/reinstall); app fully usable; profile + facts build under the anon id from session one.
  • Apple Health without login: HealthKit read is a system permission, not an account — available on either path; one tap → today’s steps + history on-device.
  • Sign in anytime later: re-offered contextually; on sign-in, /claim transfers all anon data to the account. Existing-account case keeps the account + folds in recent anon activity.
  • Integrations: Sign in with Apple · HealthKit · Supabase (/claim) · Keychain.
  • Acceptance: a new user reaches a full session via “Continue without login” (one tap past the sign-in screen, no account); signing in brings 100% of the anon profile/history into the account; reinstall (signed-out) retains it.

Multimodal Everywhere P0

  • Speak, type, or send a photo (form / equipment / a plan) — combinable in one input.
  • Integrations: LiveKit + OpenAI Realtime · Gemini (vision).
  • Acceptance: every core action is reachable by voice; photo + a spoken note is one input.

Knows You (context engine) P0

  • Captures level, goals, loves/dislikes, equipment, motivators at onboarding and continuously from conversation.
  • Music taste from Apple Music/Spotify history; live biometrics (Whoop/Apple Watch) shaping the plan.
  • Integrations: HealthKit · Whoop · MusicKit/Spotify · Supabase.
  • Acceptance: the coach references goal + a disliked movement + equipment + recovery in one recommendation.

The Vibe (adaptive sensory audio) P0 — the differentiator

  • Live mix: coach voice intertwined with music + ambient vibe (underground/forest party, stadium, calm sea…), ducked/layered as one experience.
  • Real-time adaptation: push (rally, tempo up), hold (steady), ramp-down (calm) — the coach decides to match or shift the user’s state.
  • Voice control: “give me a forest vibe,” “change the music,” “stop the vibe.” Phone pocketed, all audio.
  • Integrations: ElevenLabs (SFX worlds) · stem adaptive-music + CoreMotion (cadence→BPM) · Steam Audio (spatial “pack”) · LiveKit (mix/duck).
  • Acceptance: the user swaps world + music by voice mid-session with the coach still clear over the mix.

Music (their taste) P0

  • Connect Apple Music / Spotify; use their tracks sequenced to the session arc (banger at the peak) and adapted with the vibe.
  • Integrations: Apple MusicKit (connect + playback) · Spotify SDK/Web API.
  • Acceptance: their own music plays, paced to the session, controllable by voice.

Exercise Video Library P0

  • What: guarantees the coach’s “you’re starting X → here’s the video” for any session — designed, captured, or brought.
  • How: normalize each exercise name → look it up in a licensed exercise-video provider (several license demo clips/animations to fitness apps) that permits hosting; store the licensed clip in our DB; fall back to the built-in exercise DB or a still + a form cue if there’s no match.
  • Shared: one library powers Your Daily Session, Bring Your Own Workout, and admin-ingested templates.
  • IP boundary: we license the demo content and host it; we do not store, redistribute, or AI-recreate copyrighted clips (e.g. from another app). A captured/brought workout gives us the structure; the clip shown is always the licensed provider’s.
  • Licensing must-check: pick a provider whose license explicitly allows (a) storing the files in our DB and (b) redistribution in a commercial app — some allow stream-only. Candidates: a 3D-animation licensor (premium, host-and-own) for consistency; an exercise API (broad, fast) for MVP; own filmed footage later (moat).
  • Integrations: licensed exercise-video provider/API · built-in exercise DB (fallback) · Gemini (name match).
  • Acceptance: every exercise in a session resolves to a demo (or degrades to an image + cue); identical for designed, captured, and brought workouts.

Deliver-with-what-we-have (principle) P0

  • Value from current knowledge; ask only to sharpen, never to block; precision compounds as it learns. Applies product-wide.

Pro-Coach Backing (trust) P0

  • All guidance grounded in the pro-athlete coach’s rules; surfaced in-app + in the coach’s framing.
  • Integrations: Supabase rules engine.

Gets Smarter (memory + learning) P1

  • Full searchable in-session chat; all data tailors workouts, music, vibes, coach over time.
  • Integrations: Supabase (user_facts) · Langfuse.
  • Acceptance: a preference stated once is honored later without repeating.

Admin / Content (behind the scenes)

Admin: Reference Workout Ingestion P0 (admin-only)

  • What: an admin-only tool to turn reference training material into structured, reusable programming knowledge that makes our coach’s original designs sharper.
  • How: admin uploads a screen recording → Gemini segments it and extracts the structure — exercise sequence, sets/reps/tempo, rest intervals, coaching cues, progression — stored in Supabase as workout templates + coaching knowledge.
  • What is stored: the structure/metadata only, used as reference the coach designs from (blended with dad’s system + sports science). The source video clips are never stored or served. Each exercise maps to the licensed Exercise Video Library for its demo.
  • Framing: ingested programming is internal reference to inform original coach-authored workouts, not 1:1 clones — defensible and on-brand (“designed by your coach,” not “copied from an app”).
  • Admin-gated: restricted to the admin; not a user feature. Reuses the Show Me capture/upload mechanism.
  • Integrations: Gemini (video understanding/segmentation) · Supabase (templates/knowledge) · Show Me capture · admin tool.
  • Acceptance: an uploaded recording yields a structured template (exercises + sets + rest + cues) in the DB; a session played from it shows licensed demos per exercise; no source video is retained.

User #1 — Fitness

Your Daily Session P0

  • Daily 60-min from the coach rules × the user’s arc; spoken gist + structured list; a video per exercise from the Exercise Video Library; chat to tailor (“30 min,” “I’m wiped”) while respecting progression.
  • Integrations: Supabase · Gemini (segmentation) · Exercise Video Library (licensed provider); own filmed footage is a later moat upgrade.
  • Acceptance: by morning a session + gist exists; a change request updates it in one turn, rules-grounded.

The Coach (real-time) P0

  • Context start; control it (“speed up intro,” “skip to exercise,” “how am I doing”); silent HR + welcome check-ins that override the number; video on “starting X”; times exercises + rests; per-exercise HR; specific, earned, not-too-frequent motivation; cool-down tone shift.
  • Integrations: LiveKit + OpenAI Realtime · Whoop/Apple Watch (live HR).
  • Dependency: the structured-workout model (exercises→sets→rest) — the linchpin.
  • Acceptance: each exercise + rest timed, HR tracked per exercise, video cued on request, tone shifts for cool-down.

Bring Your Own Workout P1

  • Multimodal intake (voice / text / photo / screen-recording, parsed — reuses the Show Me capture). Progressive, non-blocking detail — runs on whatever it has: rich → precise timing/HR/videos/cool-down; sparse (“legs, ~45 min”) → infers defaults from profile + typical patterns; light follow-ups, freely declined, fillable later.
  • Save/reuse/edit (“your Tuesday push day”); vet, don’t override (the plan stays theirs); full experience wrap.
  • Integrations: Gemini vision (parse) · LiveKit+Realtime (dialogue) · Supabase (save).
  • Acceptance: minimal info still yields a full experience; more detail visibly improves precision; a saved workout returns next week needing only what changed.

Hype Film P1

  • Short video generated daily from context + past workouts to attack starting; assembly pipeline (LLM script → TTS → music → visuals), personalized + in the coach’s voice.
  • Integrations: video-assembly (TTS + music + visuals) · Supabase.

The Wrap (recap) P1

  • End-of-session breakdown — every exercise, HR + indicators, progress vs before — + ending motivation.
  • Integrations: Supabase · Whoop/HealthKit.
  • Acceptance: the recap lists per-exercise detail + HR and ends on a lift.

User #2 — Steps / Walk (wedge — ships earliest, lowest dependency)

Your Step Goal P0

  • Personalized from baseline + schedule + level; adapts over time; consistency-and-delight over a hero number.
  • Integrations: HealthKit/Health Connect · Supabase.

All-Day Gap Tracking P0

  • Passive count (Apple Health/Google Fit); incidental steps count; works fully signed-out; always knows the gap; surfaced on open (pull), notifications off unless opted-in; immediate on grant; fresh via background delivery.
  • Integrations: HealthKit / Health Connect (Google Fit).
  • Acceptance: a signed-out user allows Apple Health and sees the live gap within seconds, then gets an offered walk — no account.

Gap-Close Offer P0

  • A specific, delightful walk sized to gap + time + mood (“1,500 → a 12-min beach walk”); always positive framing; mood by spoken word/tap/inferred.
  • Integrations: LiveKit+Realtime · ElevenLabs · MusicKit.
  • Acceptance: the offer would plausibly close the gap; declining is frictionless and un-nagged.

Walk Coach P0

  • Context start, then paces to hit the target in the available time via live steps, pace (GPS), HR; welcome check-ins that override numbers; feel-good milestones; you control it (shorter, quieter, “just walk with me”). Companion, not pusher.
  • Integrations: CoreLocation/GPS · HealthKit · Whoop/Apple Watch · LiveKit+Realtime.
  • Acceptance: on a timed walk the coach keeps the user on track for the goal within their window.

Finish & Streak P0

  • Celebration on hitting it (audio + afterglow); shame-free miss with a small top-up; recap (steps/distance/pace/HR) + streak framed as a win; calm close.
  • Integrations: HealthKit · Supabase.
  • Acceptance: hitting the goal feels rewarding; missing produces an encouraging, low-pressure response — never a red “failed.”

Future / low

Wind-Down / meditative P3 (low)

  • Evening decompress (walk → breathe → dark screen + fading soundscape → hand off to Sleep Focus); reusable Breathing + SleepMode components.
  • Integrations: App Intents/Shortcuts (Sleep Focus) · Core Haptics (breathing) · ElevenLabs (soundscape).

Visual Layer P3

  • On AI glasses, the vibe becomes visual atop the audio.
  • Integrations: AI-glasses SDK.
Two anchors for the build:
• The P0 gap is the Vibe stack + music playback (ElevenLabs · adaptive music/CoreMotion · Steam Audio · MusicKit/Spotify) — the integrations that create the experience, the P0 the user cares about most. Brain/transport/data/biometrics/vision are already built.
• The structured-workout model is the recurring linchpin (daily session · per-exercise HR/timing · recap · bring-your-own) — build it first; and HealthKit steps single-handedly unlocks the entire Steps wedge (so it can ship earliest).
